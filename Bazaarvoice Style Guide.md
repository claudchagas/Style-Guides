## 1. Overview & Purpose

This guide defines the linguistic and formatting standards for translating Bazaarvoice content from English into Brazilian Portuguese (pt-BR). It applies to all UI copy, submission form strings, email templates, alt text, microcopy, and UGC-related interface content.

**Scope:** Two primary content contexts:

| Context | Description |
|---|---|
| `configurationDefinitions` | UI copy and submission form questions — question-and-answer strings, form fields, project content |
| `templateDefinitions` | Email content delivered to client customers following consumer-generated content interactions |

---

## 2. Target Audience & Use Cases

**Industry:** IT — B2B Software
**Domain:** Consumer ratings and reviews — collecting, syndicating, and optimizing UGC across retailers.
**End audience:** Online shoppers and product consumers interacting with submission forms and follow-up emails.

---

## 3. Tone & Register

### 3.1 General register

Use a **formal, professional** tone throughout. Colloquial expressions are inappropriate in all contexts.

Address the reader using the **formal second person** ("você" with formal conjugation). Never use "tu" or informal contractions.

### 3.2 Voice

Write in **active voice**. Avoid passive constructions.

Use short, impactful sentences. Prioritize clarity and concision. Use few adjectives and adverbs — let the action carry the copy.

### 3.3 Tone by content type

| Content type | Tone guidance |
|---|---|
| `configurationDefinitions` (form questions) | Direct, clear, neutral. Functional language suited to a submission form. |
| `templateDefinitions` (follow-up emails) | Professional and polite. Warm enough for customer communication, formal enough for a B2B-to-consumer context. |

---

## 4. Translation Approach

### 4.1 Fluency over literalism

Translate into natural, idiomatic Brazilian Portuguese. Do **not** translate word for word or preserve English word order. Restructure sentences freely — especially in UI, product, and marketing copy — when restructuring produces a more natural result.

**Do:** Choose the formulation that sounds like it was originally written in Portuguese.
**Don't:** Produce calques, literal noun-list constructions, or any phrasing that reads as translated.

When the English source compresses multiple concepts into a short phrase, expand or reorganize it into a clear Portuguese formulation. Use compound constructions or explanatory wording where natural.

---

## 5. Writing Style

- Write in **prose**. Do not use bullet points.
- Use **short sentences**. One idea per sentence.
- Use **active voice**. Avoid passive constructions.
- Use **clear, simple language**. Avoid AI clichés, buzzwords, and jargon.
- Use **few adjectives and adverbs**. Focus on practical, direct expression.
- **Address the reader** using "você" and the corresponding possessive "seu / sua".

---

## 6. Grammar & Syntax Conventions

### 6.1 Second-person pronoun

Use the **formal "você"** consistently. Do not mix registers within a string or across related strings in the same form or email.

### 6.2 Abbreviations

**Not acceptable.** Write all terms in full. Do not introduce abbreviations even for commonly abbreviated expressions.

### 6.3 Acronyms

If an acronym appears in the source, include the equivalent in the translation. On first mention per document or screen, write the full term followed by the acronym in parentheses. Use the acronym alone in subsequent mentions.

---

## 7. Punctuation, Capitalization & Formatting

### 7.1 Punctuation rules

| Element | Rule |
|---|---|
| Em dashes (—) | Do not use |
| Bullet points | Do not use |
| Semicolons | Avoid |
| Hashtags | Avoid |
| Emojis | Avoid |
| Asterisks | Avoid |
| Exclamation marks | Use sparingly — only for genuine excitement or emphasis |

### 7.2 Capitalization

Apply standard pt-BR capitalization rules:

- Sentence case for all headings and UI labels — capitalize only the first word and proper nouns.
- No unnecessary capitalization mid-sentence.
- Do not capitalize job titles unless they open a sentence.

---

## 8. Do Not Translate

The following element types must remain in English exactly as they appear in the source:

| Category | Examples |
|---|---|
| Website names | eurail.com, bazaarvoice.com |
| Branded names | Bazaarvoice |
| Usernames | Any @handle or account identifier |
| Product names | All Bazaarvoice product names |
| Email addresses | user@domain.com |
| URLs | https://... |

---

## 9. Special Instructions — UI Element Handling

### 9.1 Parenthetical UI translation format

When translating UI elements, use the following parenthetical format:

```
English Source Content (Translation)
```

The English source text is preserved first, followed immediately by the pt-BR translation in parentheses. Do not alter this structure.

> **Example:**
> Source: `Submit Review`
> Output: `Submit Review (Enviar avaliação)`

This format applies to all UI elements where the instruction is present. Apply it consistently across all strings in the same job unless explicitly instructed otherwise.

---

## 10. Do's and Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Use formal "você" throughout | Use "tu" or informal contractions |
| Write in active voice | Use passive constructions |
| Restructure sentences for natural pt-BR flow | Preserve English word order literally |
| Use plain prose | Use bullet points or lists |
| Use the parenthetical format for UI elements: Term (Tradução) | Omit the English source from UI element output |
| Keep product names, URLs, and branded names in English | Translate Bazaarvoice product or brand names |
| Write all terms in full | Use abbreviations |
